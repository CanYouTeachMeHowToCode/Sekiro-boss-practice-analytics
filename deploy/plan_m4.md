### 安全

- 防火墙只开 22（SSH）、80、443。
- 数据库和后端不对外开端口，只有 Caddy 对外。
- **HTTPS**：Caddy 自动申请证书。地址用 sslip.io 的免费域名（由 IP 生成，形如 `1-2-3-4.sslip.io`），不用买域名。如果证书申请不下来，就买一个域名（每年约 $10）。
- **共享密码**：整个网站先要输一道共享密码（Caddy 的 basic auth），只发给测试者，进去后再注册登录。这样不用改代码，拿到网址的陌生人也注册不了。
- `COOKIE_SECURE=true`，代码已经支持。
- 数据库密码随机生成，只存在服务器的 `.env` 里。
- SSH 用 `gcloud compute ssh`，密钥由 Google 管理。
- 系统安全更新自动安装。

### 仓库里要加的文件

放在新分支 `feature/test-deployment` 的 `deploy/` 文件夹里：

| 文件 | 作用 |
|---|---|
| `compose.server.yml` | 叠加在 `docker-compose.yml` 上：去掉数据库、后端、前端的对外端口，加 Caddy（80/443），设 `COOKIE_SECURE=true` |
| `Caddyfile` | HTTPS、共享密码，转发到前端（前端的 nginx 再转发 `/api`）；上传上限沿用现在的 2 GB |

| `deploy.sh` | 每次更新：检查队列为空 → 拉代码 → 构建 → 重启 → 检查网站能打开、worker 的解码检查通过 |

| `README.md` | 英文的部署说明，包括开机器的 gcloud 命令 |

### 从开机器到上线，按顺序

1. **你**：装 Google Cloud CLI，运行 `gcloud auth login`（浏览器里登录），再运行 `gcloud config set project <项目 ID>`。
2. **我**（你同意后）：开机器，分配固定 IP，设防火墙。
3. **我**：SSH 上去运行 `setup.sh`。仓库是公开的，服务器不用 GitHub 密钥就能取代码。
4. **我**：从你电脑把分析数据文件夹（506 MB）传到服务器的 `/srv/sekiro/analysis-data`。
5. **我**：写好服务器的 `.env`，运行 `deploy.sh`。第一次要从头构建所有镜像，大约 15–20 分钟。
6. **核对**（全部通过才发给测试者）：
   - worker 日志显示 `pipeline: v2 on cpu`，说明解码检查通过；
   - 上传「无双难短血条弦一郎2」（442 MB），报告要和研究工具完全一致：3 次失败，时间、类型、招式、有没有把握、候选顺序都相同，分数最多差 0.001。如果不一致，就先不让测试者用，查清原因。服务器的 CPU 和你的不同，解码或计算结果有可能出现差别；
   - 量出三个数：这段录像的分析耗时（你电脑的 CPU 上是 7 分 17 秒）、worker 的内存峰值、从你家上传的速度；
   - 上传一段无关视频，要被拒绝；
   - 两个账号互相看不到录像，没登录看不到任何录像；
   - 重启机器后，录像、报告、片段都还在。
7. **你**：把网址、共享密码和测试须知（我起草）发给测试者。
