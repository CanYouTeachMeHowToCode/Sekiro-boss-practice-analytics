# Sekiro Boss Practice Analytics

[English](README.md) | 简体中文

一个用于记录《只狼：影逝二度》Boss 攻略尝试、失误以及玩家长期进步情况的 Web 应用。

## 为什么需要这个工具

只狼玩家经常卡在苇名弦一郎、剑圣 苇名一心、义父、破戒僧这样的 Boss 上，但大多数玩家并没有一种结构化的方式来了解：

* 哪些 Boss 招式或技能让自己死得最多
* 自己是否真的在进步
* 哪个阶段是主要瓶颈
* 击败每个 Boss 需要尝试多少次

Sekiro Boss Practice Analytics 把每一次 Boss 尝试转化为结构化的练习数据。

应用不要求玩家记住详细的战斗统计数据，而是只关注玩家在每次尝试后真正能回忆起来的信息，比如打到了哪个阶段、最后是被哪个招式击败的。

应用随后利用这些历史记录，识别反复出现的弱点和进步趋势。

---

## V1 — 手动记录的尝试分析

V1 是一个手动记录 Boss 尝试、并对失败原因进行分析的工具。

玩家记录每次打到了哪里、是什么结束了这次尝试，应用据此找出最常导致失败的招式和瓶颈阶段。

### V1.0 — 已完成

V1.0 以**苇名弦一郎**作为代表性 Boss，实现了完整的初始端到端流程。

V1 的目标刻意不追求覆盖所有只狼 Boss，而是在扩充数据之前，先验证完整的应用架构和用户流程。

### V1 功能

* 浏览已支持的只狼 Boss
* 查看 Boss 的阶段和招式
* 记录 Boss 尝试
* 记录这次尝试是胜利还是失败
* 记录打到的阶段
* 记录最终导致失败的 Boss 招式
* 当不确定是哪个招式时，支持选择 `Other`（其他）和 `Not Sure`（不确定）
* 为尝试添加可选备注
* 查看尝试历史
* 查看总尝试次数统计
* 找出最常导致失败的招式
* 找出主要瓶颈阶段
* 查看基础的进度分析

### V1 用户流程

```text
选择 Boss
    ↓
Boss 仪表盘
    ↓
记录尝试
    ↓
结果 + 到达阶段 + 失败招式
    ↓
保存尝试
    ↓
尝试历史
    ↓
失败分析
```

V1 刻意聚焦于一个小数据集和一条完整的纵向功能链路，而不是广泛的 Boss 覆盖。

## V2 — 结构化的只狼分析平台

V2 会把 V1 原型扩展成一个更完整的只狼练习分析平台。

V2 的主要重点，是从一个基于 JSON 的小型 MVP，转向一套能够支持多个 Boss 和更大量尝试历史的结构化持久化与分析架构。

### V2 计划功能

#### PostgreSQL 持久化

用 PostgreSQL 取代 V1 的 JSON 持久化层。

V2 的关系模型大致如下：

```text
Game（游戏）
 └── Boss
      ├── Phase（阶段）
      ├── Move（招式）
      └── Attempt（尝试）
           └── Failure Move（失败招式）

Phase ←── 多对多 ──→ Move
```

招式属于某个 Boss，即使出现在多个阶段，也只存储一份。另有一张关联表记录每个招式出现在哪些阶段，因此死于同一个招式的尝试，无论发生在哪个阶段，都会指向同一条招式记录。

这会引入：

* PostgreSQL
* SQLAlchemy
* 数据库关联关系和外键
* 使用 Alembic 进行 schema 迁移
* 把现有的 V1 JSON 数据迁移到 PostgreSQL

当底层持久化层从 JSON 切换到 PostgreSQL 时，前端的 API 契约应基本保持不变。

#### 扩充 Boss 覆盖

V2 会在苇名弦一郎之外加入更多主要的只狼 Boss。

可能加入的 Boss 包括：

* 蝴蝶夫人
* 狮子猿
* 破戒僧
* 巨型忍者 枭
* 义父
* 剑圣 苇名一心

Boss 覆盖会逐步扩充，而不是一开始就试图做成一部完整的只狼百科。

#### 更丰富的 Boss 数据

Boss 招式可以包含更多结构化信息，例如：

* 出现在哪些阶段
* 招式类型
* 攻击描述
* 前摇特征
* 应对方式（counter）
* 常见失误

这些 Boss 元数据也会为未来的实战录像分析打下更坚实的基础。

#### 更完善的进度分析

V2 会超越简单的汇总计数，引入以进步为导向的分析，例如：

* 随时间变化的尝试进度
* 最近几次尝试中到达的阶段
* 全部历史与最近一段时间的失败模式对比
* 常见失败招式的变化
* 首次胜利前所需的尝试次数
* 基于玩家自己尝试历史的 Boss 难度

例如：

```text
全部尝试

飞渡浮舟 导致的失败：12 次

最近 10 次尝试

飞渡浮舟 导致的失败：2 次
```

这可以作为某个弱点正在随时间减少的证据。

除非应用拥有足够的数据来正确计算，否则 V2 不会展示诸如招式成功率之类的指标。

#### 只狼总览仪表盘

除了单个 Boss 的仪表盘，V2 还可能提供一个游戏级别的分析仪表盘，展示以下信息：

* 挑战过的 Boss 数
* 已击败的 Boss 数
* 总尝试次数
* 需要最多尝试次数的 Boss
* 最近的练习活动
* 在多个 Boss 之间的进度

#### 数据溯源

Boss 和招式信息可以附带来源元数据，让游戏知识能够追溯到可靠的来源，比如社区文档或 Sekiro Wiki 的相关页面。

#### 部署与 CI/CD

V2 可能会把当前的开发流程扩展为独立的部署环境：

```text
feature/*
    ↓
dev
    ↓
CI
    ↓
Staging（预发布环境）

main
    ↓
CI
    ↓
Production（生产环境）
```

可能加入的内容包括：

* 自动化后端测试
* 前端类型检查与构建
* 集成测试
* Docker 镜像构建
* 自动部署到预发布环境
* 从稳定版本部署到生产环境

## 技术栈

### V1.0

* **后端：** FastAPI
* **持久化：** JSON
* **前端：** React + TypeScript
* **部署：** Docker

V1 刻意使用 JSON 持久化，因为初始数据集很小，主要目标是验证完整的应用流程。

### V2 计划

* **后端：** FastAPI
* **数据库：** PostgreSQL
* **ORM：** SQLAlchemy
* **数据库迁移：** Alembic
* **前端：** React + TypeScript
* **部署：** Docker
* **CI/CD：** GitHub Actions
