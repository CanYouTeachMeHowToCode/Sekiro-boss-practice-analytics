# 弦一郎真实数据计划（V4，原版）

从 V3 完成、V4 尚未开始的状态出发，到"弦一郎的所有可能招式都被捕捉并 100% 准确地记录下来"为止的完整步骤。

- 规则集：**只做原版**，不包含 Resurrection 模组。
- 范围：弦一郎出现的**所有战斗**。包括序章、天守阁（3 个阶段）、剑圣战里的巴流 苇名弦一郎，以及心中的弦一郎。如果要缩小范围，在第 4 步确定。
- 每一步都标明谁来做：「你」是项目负责人，「Claude」是 AI 助手。
- 规则：**哪些内容算真实数据，由你最终敲定。** Claude 只负责整理证据、提出建议。

---

## "100% 完成"的定义

只有同时满足下面三条，才算完成：

1. **读取准确**：所有录像里提取出的动画 ID 全部正确。
   - 每一个都通过格式校验、白名单校验和连续性校验；
   - 被标记为可疑的帧全部经过人工核对；
   - 随机抽查的帧零错误。
2. **覆盖完整**：弦一郎所有角色 ID 里的**每一个攻击类动画**，都满足以下二者之一：
   - 在录像里实际出现过，并且知道是哪场战斗、哪个阶段；
   - 有证据说明为什么不会出现，比如只用于过场、属于其他战斗、游戏中没有用到，并且经过你确认。

   "无法解释的攻击动画"数量为 **0**。
3. **语义目录经你确认**：每个动画或动画链对应哪个语义招式，都由你逐条确认。

说明：

- "所有可能的招式"是相对于**录制时的游戏版本**而言的。游戏更新后需要重新检查。
- 如果某个动画始终录不到，也找不到不出现的证据，就如实标记为 `unknown`，不会凭推测把它归入任何一类。CLAUDE.md 第 31 节规定，没有证据时不能宣称绝对完整。

## 总流程

```text
 0. 发布 V3
      ↓
 1. 研究基础（V4 M1）：分支、目录、本地配置、工具
      ↓
 2. 静态全集：解包各个角色 ID，解析 TAE，筛出攻击动画（集合 E）
      ↓
 3. 录像提取管线：从画面读取动画 ID → 事件日志；先在试录上达到 100%
      ↓
 4. 确认角色 ID ↔ 战斗 ↔ 阶段
      ↓
 5. 系统录制：常规对战 + 诱发清单 → 实际出现的集合 R ──┐
      ↓                                              │ 还有没解释的攻击动画
 6. 覆盖率检查：E 和 R 对比                           │ → 针对性补录（回到第 5 步）
      ↓ 全部有解释                                   ←┘
 7. 衔接图 + 语义目录（V4 M4）→ 你逐条确认
      ↓
 8. 完整性审核 + 差距报告（V4 M5）→ 你签字确认 → 完成
```

## 第 2 步：静态全集（集合 E）

**你**

1. 在 DS Anim Studio 里打开 `c7101`、`c7103`、`c7111`，分别记录：
   - 模型外观：有没有穿铠甲、和 `c7100` 是否相同；
   - 动画数量和编号范围；
   - 有没有攻击动画，也就是带 `InvokeAttackBehavior` 事件的动画。
2. 把 `c7100`、`c7110`、`c7101`、`c7103`、`c7111` 的动画文件解包到第 1 步定好的目录里。如果 DS Anim Studio 能直接导出 TAE 数据，也可以用导出的结果。

**Claude**

1. 写脚本解析 TAE。具体用哪个库，要看文件格式，到时候再定，比如 SoulsFormats 这类。每个动画导出以下信息：
   - 动画 ID、帧长、帧率；
   - 全部事件：类型、起止帧、参数；
   - 攻击参数编号，比如 `ATK 7100150`。
2. **自动筛出攻击动画**：带攻击类事件的就算攻击候选，其余归为移动、受击、防御等。
3. 按攻击参数分组，并从 `JumpTable` 事件里尽量推出"哪个动画可以接哪个动画"。
4. 结果写入 `engine/<角色ID>_animations.json`。这些都是派生出来的元数据，可以提交；原始文件不提交。

**你**：在 DS Anim Studio 里抽查自动分类的结果，特别是被判为"非攻击"的那些。

**完成标准**：得到每个角色 ID 的攻击动画候选清单，也就是集合 E，并且经过你抽查。

## 第 3 步：录像提取管线

**你**

1. 录像设置：
   - 用 OBS 录制，原始分辨率，不缩放；
   - 60fps，高码率，比如 CQP 16 左右；
   - 开发者菜单显示在固定位置，最好放在背景较暗的地方。
2. 提供一张原始分辨率的截图，画面上要显示着编号。确认三件事：
   - 编号的格式；
   - 哪一行是 Boss 的动画；
   - **有没有显示动画当前的帧数或时间**。
3. 录一段 30–60 秒的弦一郎试录。

**Claude**

1. 在截图上定好编号区域，从试录里截取字符模板：0–9、`a`、`_`。
2. 写提取脚本：
   - ffmpeg 逐帧解码，只截取编号所在的小区域；
   - 二值化，按字符切开，逐个和模板比对。
3. 三道校验：
   - 格式必须符合 `a\d{3}_\d{6}`；
   - 必须在第 2 步得到的白名单里；
   - 只出现一两帧的"跳变"判定为误读，用前后帧纠正。
4. 处理"同一个动画连续出现两次"：
   - 如果菜单显示帧数，就靠帧数归零来判断重新开始；
   - 如果不显示，这个问题会如实写进限制说明，并想别的办法补救。
5. 实测菜单的刷新频率和延迟，检查极短的动画会不会被漏掉。
6. 输出事件日志 CSV，格式和"真正的日志文件"保持一致：
   - 录像哈希、开始/结束帧、开始/结束时间、动画 ID、标记。

**质量门槛**：在试录上，把提取出来的**每一次动画切换**都和画面逐一核对，必须零错误。之后每一批录像，都要复查所有被标记的帧，并随机抽查一部分。

**完成标准**：试录零错误，并且管线可以重复运行。

## 第 5 步：系统录制（集合 R）

**你**：每场战斗、每个阶段，都要录**常规对战**，加上下面的**诱发清单**，每一项至少录几次：

- 只弹刀，不进攻
- 只防御
- 频繁喝葫芦
- 使用道具和义手忍具
- 拉开距离，在远处引诱
- 贴身连续进攻
- 频繁跳跃
- 站到高处，或者绕到 Boss 身后
- 在每个阶段都故意死几次，保证每个阶段都有足够的录像
- 第 6 步报告里列出的"还没录到的动画"，针对性地去引出

每段录像都记下：游戏版本、规则集（原版）、哪场战斗、画质设置、阶段切换的大致时间。

**Claude**：每批录像都会

1. 运行提取管线，生成事件日志，并复查所有被标记的帧。
2. 更新统计：
   - 每个动画在每个战斗、每个阶段出现的次数；
   - 动画之间"谁接谁"的统计；
   - 饱和曲线：每多录一场，新出现了几个攻击动画。

**完成标准**：见第 6 步。

## 第 6 步：覆盖率检查

**Claude**：把集合 E（静态攻击动画）和集合 R（录像里实际出现的动画）对比，列出：

- 在 E 里、但从来没录到的攻击动画，同时附上它的帧长、攻击参数，以及在 DS Anim Studio 里的编号，方便你去看它长什么样；
- 录到了、但不在 E 里的动画。这种情况一般说明白名单或分类有问题。

对每个没录到的动画，按下面的顺序处理：

1. **你**在 DS Anim Studio 里看它是什么动作，判断它可能在什么条件下出现，然后去补录。
2. 怎么录都录不到的，**Claude** 尝试从游戏的参数和 AI 脚本里找证据，看这场战斗是否根本不会用到它。这个方法能不能行得通，要实际查过参数文件才知道，现在只是推测。
3. 仍然无法确定的，标记为 `unknown`，并在报告里列出。

**完成标准**：

- 每个攻击动画都处于以下三种状态之一：已录到、有证据说明不会出现、明确标为 `unknown`；
- `unknown` 的数量为 0。如果实在做不到 0，由你决定是否接受；
- 连续若干批录像，都没有出现新的攻击动画。
